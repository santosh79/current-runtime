Agents propose. Nothing happens until you approve.

Current is change control for AI agents. The agent hands over a complete proposal. Current validates it, waits for your decision, applies it, and records every step in a hash-chained log.

Why not just use Claude Code or Codex?

You can. The difference is where the action happens. In a typical agent, a tool call is the action: the file is written the moment the model decides to write it. In Current, the agent can't act at all.

A typical coding agent

model decides, file is written
model decides, command runs
you approve step by step, as it goes

Review happens around actions that are already underway.

Current

model hands over typed intents
runtime decodes and validates
you approve, send back or reject
runtime applies, verifies, records

A small trusted interpreter is the only thing that touches your project, and only after an approval is on the record.

A proposal, not a tool call.

The agent sees only the files it asks for that the read policy allows, and can only propose from nine intent types. Approving and applying are separate steps. Only allowlisted commands run.

Check the work. Not the word.

Review the exact edits and commands, or pass the JSON review to another agent. Claims are checked against what actually ran, and a false claim fails the workflow.

Every change has a history.

When someone asks why a line changed and who approved it, the answer comes from a commit log, not from asking the model to explain itself.

Between the proposal and your project

A proposal does nothing on its own. Five steps stand between it and your files, and each is recorded as an event.

  1. Decode

    The model's reply is untrusted bytes. It becomes typed intents from a closed set, or it is rejected. Nothing is interpreted.

  2. Validate

    Paths stay inside the project, files exist, every edit matches exactly, every claim cites an earlier intent.

  3. Decide

    A person or another agent approves, rejects, or sends it back with feedback. Each revision is a new proposal with its own ID. Ten revisions by default.

  4. Apply

    A separate command. The interpreter re-checks each path against the filesystem, following symlinks, just before touching it.

  5. Check

    Claims are evaluated against recorded results. The first failed effect or false claim stops the workflow. Effects are not rolled back.

Nine intents. Anything else is rejected.

The agent speaks a closed vocabulary. Before proposing, it can look around with the three read-only intents: up to 20 per reply and 8 rounds, filtered by the read policy and recorded.

One runtime, three ways in

The CLI, the HTTP API and the MCP tools all go through the same runtime and the same rules. Review as a person, from a script, or with another agent in the loop. Pick an OpenAI or Anthropic model per task.

Every change traces back to a request

The runtime is the only thing that acts, and it records each step before taking the next. Read the chain without the model, and check that nobody quietly edited it.

The head hash fingerprints everything

Change any byte of any past commit and every link after it breaks. File contents, command output and model replies are covered too, by their SHA-256 ids.

Verified on every start

A gap, a broken link or corrupt bytes stop the runtime, naming the file. Commits are fsynced before anyone hears of them.

Rules enforced at commit time

One pure reducer decides every transition. No apply without approval, no decision on a stale proposal, and of two racing approvals only one is accepted.

Replay anywhere

The log and the artifact store are the whole state. Copy the data directory to another machine and the same history rebuilds.

Control isn't a sandbox.

Current controls when an agent's proposal takes effect and records everything about it. It does not limit what an approved proposal can do. It is early software: single node, local projects.

Read this before you approve a command

  • Approved commands keep your privileges. Commands are denied unless allowlisted. Once allowed, they inherit the runtime's environment, files and network, and their arguments are unrestricted. Approving npm test approves running arbitrary code.
  • Local first, not authenticated. The HTTP API and MCP endpoint have no authentication. Anyone who can reach them can approve and apply, so keep them on loopback or behind a gateway.
  • Tamper-evident, not signed. Someone who can write the data directory can rewrite history and recompute every hash. Signed or externally published heads are planned.
  • The read policy filters by name. Dependencies, build output, .git and .env* are never shown to the model. A key in another file can be.

Works today

  • Request, review, revise, approve, reject and apply from the CLI, HTTP or MCP
  • Claims verified against results
  • Hash-chained, segmented log, verified on every start
  • Content-addressed artifacts for every input and output
  • OpenAI and Anthropic models, chosen per task
  • Default-deny command allowlist

Planned

  • current export and current replay: re-run elsewhere and diff
  • current verify: check the chain and every artifact
  • Signed or externally anchored log heads
  • Approval policies and authenticated approvers
  • Command timeout, output cap and environment filtering
  • Atomic apply, and sandboxed commands

Make your first proposal

You need Elixir 1.19 on Erlang/OTP, git, make and bash, and an OpenAI or Anthropic API key. The full setup guide has the details.

Build Current

git clone https://github.com/santosh79/current.git
cd current
mix deps.get
mix compile
make client

Start the runtime

# in the repository root
export ANTHROPIC_API_KEY="your-key"
# commands are denied unless allowlisted
export CURRENT_ALLOWED_COMMANDS=npm
bin/current-server

Ask for a proposal

# another terminal, repository root
export PATH="$PWD:$PATH"
current models
# use an ID from the list above
MODEL="anthropic:model-id-from-the-list"
current run "add CSRF protection to this app" \
  --dir examples/nextjs-auth --model "$MODEL"

Review, decide, apply

current review  <proposal-id>
current revise  <proposal-id> -m "add edge cases"
current approve <proposal-id> -m "reviewed"
current apply   <proposal-id>
current events  <workflow-id>

Want a proposal that can never be applied? Use current plan instead of current run.
